# spread_terminal

Терминал для анализа спредов квартальный фьючерс − вечный в реальном времени
и бумажного прогона стратегии по spread_rate. Заявок не выставляет.
Django + PostgreSQL, данные Finam Trade API, Мосбиржи, ЦБ и Bybit. Время везде UTC,
таймфрейм только час (`TIME_FRAME_H1`).

`spread_rate = raw − спот · (RUONIA − иностранная ставка) / 100 · дни / 365`,
где `raw = квартал − вечный`.

## Пары

| Пара | Ноги | Иностранная ставка |
|---|---|---|
| CNY, USD, EUR | CR/Si/Eu − CNYRUBF/USDRUBF/EURRUBF | SHIBOR, DFEDTARU, €STR |
| GOLD, SILVER | GL/S2 − GLDRUBF/SLVRUBF, цена за грамм | нет, только RUONIA |
| TRIGD, TRISV, TRIGL | GD·SI − GLDRUBF, SV·SI − SLVRUBF, GD·SI − GL | RUONIA + ставка ФРС |
| BTC (Bybit) | квартал − вечный BTCUSDT | EWMA14 8-часового фандинга |
| SICAL, EUCAL, CRCAL | секонд − фронт Si/Eu/CR | как у USD/EUR/CNY |
| GDCAL, SVCAL | секонд − фронт GD/SV, доллары | ставка ФРС, рублёвой нет |
| TRIGD2, TRIGL2 | TRIGD и TRIGL на вторых кварталах | RUONIA + ставка ФРС |
| BRNYMEX | BR Мосбиржи − BZ NYMEX, месячные, $/барр. | нет, fair = 0 |
| CRCNH | CR × CNH × 1000 − Si, CNH — CME, пункты Si | нет, fair = 0 |
| SI6E | Si × 6E − Eu, 6E — CME, пункты Eu | нет, fair = 0 |
| NGCAL | календарь NG Мосбиржи одним инструментом (NGX6NGZ6), $/MMBtu | нет, fair = 0 |
| NGNYMEX | NG Мосбиржи − NG NYMEX месяцем позже (NGZ6 ↔ NGF27), $/MMBtu | нет, fair = 0 |
| TRIGDS | GD·SI − GLDRUB_TOM: TRIGD на споте золота, без фандинга | RUONIA + ставка ФРС |

Лоты: валюта 1000, золото 1 г, серебро 100 г, TRIGD 1 унция, TRISV 10 унций.

Календарь: `raw = секонд − фронт`, `fair = спот · (r − r_foreign) / 100 · (t секонда − t фронта) / 365`.
Окно и склейка — фронта: в третий четверг декабря после склейки SiZ2026 пара
SiZ2026/SiH2027 сменяется на SiH2027/SiM2027. Своих инструментов у календарей
и секондов нет, поле `base` пары говорит, чьи кварталы брать. Фандинга у календаря нет.

BRNYMEX: ICE у Финама нет, вторая нога — BZ (Brent Last Day Financial, `BZF27@XNYM`),
он рассчитывается по цене ICE Brent. NYMEX на месяц впереди: BRZ2026 ↔ BZF2027.
Окна — по Мосбирже: BR месяца M ближний весь месяц M−1, склейка — последний
рабочий день Мосбиржи этого месяца, 20:50 UTC (BRZ2026 → 30.11.2026,
BRF2027 → 30.12.2026). Нерабочие дни Мосбиржи в конце месяца — `MOEX_HOLIDAYS`
в `market/expiry.py`, их нужно дополнять на новый год. Бар есть
только в будний час Мосбиржи, где свечи есть у обеих ног. `raw = BR − BZ`,
fair = 0, лот 1000 баррелей (1 BZ против 100 BR). Лонг входит без правила
знака, порога `MIN_PRICE_SPREAD` нет. Календарь в `market/brent.py`.

Кросс-пары (`market/cross.py`): окно — квартал CME, он истекает за два рабочих
дня до третьей среды, на три дня раньше Мосбиржи; в этот день все три ноги
переходят на следующий квартал. Бар — только в будний час Мосбиржи, где есть
свечи всех трёх ног. Даты экспирации CME `ensure_contracts` и `add_extra_spreads`
берут из Finam (`/v1/assets/{symbol}`), без ключа — по правилу биржи (`market/expiry.py`).

Газ (NGNYMEX и календарь NGCAL, `market/ngnymex.py`, `market/ngcal.py`): NYMEX на
месяц впереди, NGX2026 ↔ NGZ26@XNYM. Склейка — последний рабочий день месяца
контракта Мосбиржи, 20:50 UTC (NGX2026 → 30.11.2026). Сами ноги истекают на
несколько дней раньше (за три рабочих дня до первого числа месяца NYMEX), в эти
дни общих баров нет и спред не строится.

NGCAL — готовая котировка Мосбиржи (NGX6NGZ6@RTSX), ног у него нет; уровни
абсолютные, в $/MMBtu (spot бара = 1). Ноги NG Мосбиржи (NGZ2026, вид FOREIGN,
с окном) нужны только NGNYMEX и принадлежат ей. Если ноги остались у NGCAL
(старый `import_tv`), `fix_ng_legs --dry-run` покажет их, `fix_ng_legs`
перенесёт к NGNYMEX и пересчитает обе пары.

## Запуск

Развёртывание на сервере (nginx, gunicorn, systemd, перенос базы) — `deploy/README.md`.

`.env` в корне: `DJANGO_SECRET_KEY`, `POSTGRES_PASSWORD`, `FINAM_API_SECRET`
(и при необходимости `POSTGRES_DB/USER/HOST/PORT`).

```
python manage.py migrate
python manage.py add_usd | add_eur | add_gold | add_silver | add_tri | add_btc   # нужные пары
python manage.py add_seconds        # календари и треугольники на секондах, после базовых пар
python manage.py add_brent          # BR − BZ NYMEX и месячные контракты
python manage.py add_extra_spreads  # CRCNH, SI6E, NGCAL, NGNYMEX, TRIGDS
python manage.py sync_rates
python manage.py sync_funding
python manage.py sync_bars          # Finam отдаёт час примерно за 30 дней
python manage.py build_spread
python manage.py runserver
```

Поиск инструментов Finam: `python manage.py finam_search NG --mic EDT` — по части
тикера, символа или названия и по части MIC (`--mics` — все биржи, `--bars` —
сколько часовых баров у найденных). Список всех активных инструментов
скачивается постранично из `/v1/assets/all` раз в сутки в `var/finam_assets.json`.

Постоянно работают `run_live` (Finam), для крипты `run_bybit` и, для радара, `run_radar`.
`run_live` копит котировки и бары в памяти и раз в 5 с пишет их пачкой,
затем пересчитывает хвост spread_rate у пар, где что-то поменялось
(календари и треугольники — вслед за своими ногами). Раз в сутки обновляет
ставки и фандинг. Символы фронта и секонда пересчитываются при каждом
переоткрытии сокета (раз в 11 минут), недостающий квартал или месяц заводится сам.
Пару USD заводит `add_usd` (`fix_usd` правит спот и масштаб у заведённой раньше вручную).

## График

`/` — спред, индикатор кэрри и PnL стратегии. Уровни, режим входа, усреднение
и цена часа (закрытие, открытие, (O+C)/2) хранятся в браузере у каждого пользователя
и уходят параметрами в `/api/spread/`. Стратегия считается на лету и в базу не пишет.
Без своих уровней берутся сохранённые у пары.
Ответ сжимается gzip, а без новых баров отдаётся как 304 по ETag;
скрытая вкладка сервер не опрашивает.
Порядок пар в списке спредов меняется перетаскиванием внутри групп Front и Second
и тоже хранится в браузере.
Рисунки: Ctrl+Z отменяет, Ctrl+Y или Ctrl+Shift+Z повторяют (в любой раскладке), то же —
кнопки на панели рисования. Перетаскивание или подбор цвета — один шаг, история
своя у каждой пары и сбрасывается при её смене или перезагрузке страницы.
Переключатель «график стратегии» в панели «Стратегия» убирает панель PnL
(сделки на спреде и их счёт остаются), выбор хранится в браузере.
Кнопка с фотоаппаратом (Alt+S) копирует изображение графика со всеми панелями и
легендами в буфер обмена; по http без https буфер браузеру недоступен, тогда
снимок скачивается PNG-файлом. Легенда индикатора «фандинг − контанго»
показывает итог и отдельно фандинг и контанго в тех же единицах.

`run_strategy --pair CNY` — то же в консоли с уровнями пары: закрытые сделки
пишет в `PaperTrade`, открытую позицию держит в `PositionState`.

## Радар

Страница `/radar/`: следы крупных участников по ногам спредов и инструментам
из админки (Радар → Инструменты радара: корень квартала `RI`, `MX` — фронт и
склейка выбираются сами, или символ Finam `IMOEXF@RTSX`; там же пороги).
Строка без галочки «следить» убирает инструмент из радара, даже если это нога
спреда: символ (`SiH7@RTSX`) или корень квартала (`Si` — все контракты Si).

Страница — терминал из виджетов (GridStack): список инструментов, график
(минуты, дельта, ОИ, маркеры), стакан, лента, аномалии. Двигать, растягивать и
убирать виджеты можно после кнопки «Редактировать» (выход — «Готово»), иначе
сетка неподвижна и не мешает графикам. Клик в списке или в ленте аномалий
меняет инструмент во всех виджетах; выбор в заголовке виджета — только в нём
(📌 возвращает к общему). Раскладка хранится в браузере (`radar-layout-v2`,
старая раскладка переносится сама), «Вернуть раскладку по умолчанию» — в меню «+ Виджет».
Данные всех виджетов приходят одним запросом `/api/radar/state/?books=…&tapes=…&feeds=…`.
Запускается отдельно, в своём терминале:

```
python manage.py run_radar            # --dump 20 — напечатать первые сообщения сокета как есть
```

Процесс подписывается на стакан (`ORDER_BOOK`) и ленту (`INSTRUMENT_TRADES`)
Finam, при подключении и раз в минуту сверяет стакан REST-ом. Раз в секунду
пишет: сделки (хранятся 3 дня), минуты со стороной агрессора и открытым
интересом (год), аномалии (90 дней), верх стакана — одна строка на символ.

Детекторы считают пороги по истории самого инструмента. Числа ниже — значения
по умолчанию, все они правятся в админке (см. «Правила сигналов»):

| Тип | Что значит |
|---|---|
| крупная сделка | заявка одной стороны (серия сделок подряд) больше 99,5-го процентиля размеров |
| проход по стакану | такая заявка прошла 3 и больше уровня, объём больше 99-го процентиля |
| стена | уровень выше 99,5-го процентиля уровней инструмента и в 5 раз больше медианного, простоял 30 с |
| стена снята / съедена | стена ушла: исполнено больше половины — съедена; меньше и в 3 уровнях от лучшей цены — снята (похоже на спуфинг) |
| всплеск объёма | минута против той же минуты прошлых дней (или последних часов), робастный z ≥ 5 |
| скачок ОИ | изменение открытого интереса за минуту, робастный z ≥ 6, с толкованием по цене |

Первые часы после запуска радар набирает статистику, аномалий почти нет: стены ищутся
после ~3 минут истории стакана. Одно событие по стенам на символ и сторону в минуту.

**Правила сигналов** (админка → Радар → Правила сигналов, `radar/rules.py`).
У каждого сигнала своя строка: включён ли он, порог, кратность, число уровней,
промежуток между сделками одной заявки, время подтверждения стены, окно в
минутах (объём и ОИ) и пауза между повторами. Поле «для кого»: пусто — для
всех, корень квартала (`Si`) — для всех его контрактов, символ (`SiZ6@RTSX`) —
для одного; пустые поля такой строки берутся из общего правила. Правила
создаёт миграция с прежними значениями; `run_radar` перечитывает их раз в
30 секунд, перезапуск не нужен. Окно больше минуты сравнивает сумму объёма
(изменение ОИ) за окно с такими же окнами за последние сутки.
Нет `FINAM_API_SECRET`, `ALGOPACK_TOKEN` или самого `run_radar` — страница
рисуется и в шапке пишет, что не подключено. AlgoPack пока только проверяет
токен; FUTOI, Super Candles и HI2 подключатся следующим этапом.

## Аналитика

Страница `/analytics/` — статистика контрактов пары по дням до экспирации
(по мотивам `gas_spreads.py`): выбор пары, ряда (сырой или очищенный), месяца
контракта или всех, исключение отдельных контрактов, параметры сделки.
Четыре графика: спред каждого контракта по дням до склейки (линии — годы),
сетка «вход × выход» с доходом сделки (% за период, годовых или доход/разброс),
движение к нулю и куда шёл спред (лонг/шорт) — обе в масштабе каждого контракта;
ниже — лучшие диапазоны. Идущий контракт в статистику не входит. Расчёт —
`analytics/core.py` без numpy, кэшируется до новых баров пары.

История контракта на странице длиннее его окна торговли: спред считается из
свечей за два месяца до склейки у месячных (BRNYMEX, NGNYMEX, NGCAL) и за два
квартала у квартальных (`HISTORY_MONTHLY`, `HISTORY_QUARTERLY` в
`strategy/rebuild.py`). Окна соседних контрактов при этом перекрываются, поэтому
история лежит в своей таблице `analytics_historybar` (ключ — пара, контракт, час);
в `strategy_spreadbar` (график, стратегия) по-прежнему только окно. Таблицу
заполняют `build_spread` и `build_analytics [--pair X]`, страница сама
дорисовывает пару раз в день. Нужны свечи за этот срок: `import_tv` грузит
файл целиком, `sync_bars` тоже берёт следующие контракты с запасом истории.

Кварталы Si и Eu — в рублях за 1000 долларов или евро, пары USD и EUR делят их
на `future_scale` 1000. `fix_quarters --dry-run` показывает по каждому кварталу
чужой пары и неверные окна, а также свечи вечного, спота и кварталов в другом
масштабе. Эталон масштаба — последние 7 дней свечей пары (Finam, живой поток),
кварталы делятся на scale; свеча, отличающаяся от него в ~1000 раз, делится
или умножается на 1000 (`market/units.py`). Без `--dry-run` всё это
исправляется, затем пересчитываются спред и аналитика. `import_tv` делает ту же
проверку при загрузке: файл TradingView `RUS_USDRUBF_1000` (вечный ×1000)
записывается уже делённым на 1000.
Другой корень: `fix_quarters --root CR --pair CNY`.

История — та, что накопилась в `strategy_spreadbar`. Старые контракты можно
загрузить выгрузками TradingView («Экспорт данных графика», CSV):
`python manage.py import_tv папка/` (сначала с `--dry-run`) — инструмент по
имени файла (`CRZ2023`, `CNYRUBF`); недостающий контракт заводится сам: квартал
Мосбиржи — у пары с этим корнем, NG — по бирже в имени файла (`NYMEX_…NGG2021`
— окно NGNYMEX, иначе нога Мосбиржи), BR/BZ — у BRNYMEX, CNH/6E — у кросс-пар;
затем `build_spread`.
Автоматически качать из TradingView нельзя: официального API нет.
