# spread_terminal

Терминал для анализа спредов квартальный фьючерс − вечный в реальном времени
и бумажного прогона стратегии по spread_rate. Заявок не выставляет.
Django + PostgreSQL, данные Finam Trade API, Мосбиржи, ЦБ и Bybit. Время везде UTC,
таймфрейм только час (`TIME_FRAME_H1`).

`spread_rate = raw − спот · (RUONIA − иностранная ставка) / 100 · дни / 365`,
где `raw = квартал − вечный`.

## Пары

| CNY, USD, EUR | CR/Si/Eu − CNYRUBF/USDRUBF/EURRUBF | SHIBOR, DFEDTARU, €STR |
| GOLD, SILVER | GL/S2 − GLDRUBF/SLVRUBF, цена за грамм | нет, только RUONIA |
| TRIGD, TRISV, TRIGL | GD·SI − GLDRUBF, SV·SI − SLVRUBF, GD·SI − GL | RUONIA + ставка ФРС |
| BTC (Bybit) | квартал − вечный BTCUSDT | EWMA14 8-часового фандинга |
| SICAL, EUCAL, CRCAL | секонд − фронт Si/Eu/CR | как у USD/EUR/CNY |
| GDCAL, SVCAL | секонд − фронт GD/SV, доллары | ставка ФРС, рублёвой нет |
| TRIGD2, TRIGL2 | TRIGD и TRIGL на вторых кварталах | RUONIA + ставка ФРС |
| BRNYMEX | BR Мосбиржи − BZ NYMEX, месячные, $/барр. | нет, fair = 0 |
| CRCNH | CR × CNH × 1000 − Si, CNH — CME, пункты Si | нет, fair = 0 |
| SI6E | Si × 6E − Eu, 6E — CME, пункты Eu | нет, fair = 0 |

| SIEUSPOT | Si × EURUSD − Eu, спот EURUSD из FX_CHECK_URL, пункты Eu | нет, fair = 0 |
| NGCAL | календарь NG Мосбиржи одним инструментом (NGX6NGZ6), $/MMBtu | нет, fair = 0 |
| NGNYMEX | NG Мосбиржи − NG NYMEX месяцем позже (NGZ6 ↔ NGF27), $/MMBtu | нет, fair = 0 |
| NGNYMEX2 | то же на следующих контрактах обеих ног (в окне NGX6: NGZ6 ↔ NGF27), вкладка Second | нет, fair = 0 |
| TRIGDS | GD·SI − GLDRUB_TOM: TRIGD на споте золота, без фандинга | RUONIA + ставка ФРС |
| TRISVS | SV·SI − SLVRUB_TOM: TRISV на споте серебра, без фандинга (`add_trisvs`) | RUONIA + ставка ФРС |
| BTCMOEX, ETHMOEX | месячный BT/EH − вечный BTCUSDF/ETHUSDF Мосбиржи, $ за монету | нет, fair = 0; фандинг вечного |

Лоты: валюта 1000, золото 1 г, серебро 100 г, TRIGD 1 унция, TRISV 10 унций.

Календарь: `raw = секонд − фронт`, `fair = спот · (r − r_foreign) / 100 · (t секонда − t фронта) / 365`.
Окно и склейка — фронта: в третий четверг декабря после склейки SiZ2026 пара
SiZ2026/SiH2027 сменяется на SiH2027/SiM2027. Своих инструментов у календарей
и секондов нет, поле `base` пары говорит, чьи кварталы брать. Фандинга у календаря нет.

BRNYMEX: ICE у Финама нет, вторая нога — BZ (Brent Last Day Financial, `BZF27@XNYM`),
он рассчитывается по цене ICE Brent. NYMEX на месяц впереди: BRZ2026 ↔ BZF2027.
Окна — по Мосбирже: BR месяца M ближний весь месяц M−1, склейка — последний
рабочий день Мосбиржи этого месяца, 20:50 UTC (BRZ2026 → 30.11.2026,
BRF2027 → 30.12.2026). Нерабочие дни Мосбиржи в конце месяца — `MOEX_HOLIDAYS`
в `market/expiry.py`, их нужно дополнять на новый год. Бар есть
только в будний час Мосбиржи, где свечи есть у обеих ног. `raw = BR − BZ`,
fair = 0, лот 1000 баррелей (1 BZ против 100 BR). Лонг входит без правила
знака, порога `MIN_PRICE_SPREAD` нет. Календарь в `market/brent.py`.

Кросс-пары (`market/cross.py`): окно — квартал CME, он истекает за два рабочих
дня до третьей среды, на три дня раньше Мосбиржи; в этот день все три ноги
переходят на следующий квартал. Бар — только в будний час Мосбиржи, где есть
свечи всех трёх ног. Даты экспирации CME `ensure_contracts` и `add_extra_spreads`
берут из Finam (`/v1/assets/{symbol}`), без ключа — по правилу биржи (`market/expiry.py`).

Газ (NGNYMEX и календарь NGCAL, `market/ngnymex.py`, `market/ngcal.py`): NYMEX на
месяц впереди, NGX2026 ↔ NGZ26@XNYM. Склейка — последний рабочий день месяца
контракта Мосбиржи, 20:50 UTC (NGX2026 → 30.11.2026). Сами ноги истекают на
несколько дней раньше (за три рабочих дня до первого числа месяца NYMEX), в эти
дни общих баров нет и спред не строится.

NGCAL — готовая котировка Мосбиржи (NGX6NGZ6@RTSX), ног у него нет; уровни
абсолютные, в $/MMBtu (spot бара = 1). Ноги NG Мосбиржи (NGZ2026, вид FOREIGN,
с окном) нужны только NGNYMEX и принадлежат ей. Если ноги остались у NGCAL
(старый `import_tv`), `fix_ng_legs --dry-run` покажет их, `fix_ng_legs`
перенесёт к NGNYMEX и пересчитает обе пары.

Крипта Мосбиржи (`add_crypto`, `market/roll.py: crypto_month_points`): оба
фьючерса — на один индекс (MOEXBTC, MOEXETH), котировка в долларах за монету.
Срочные месячные (BTZ6, EHZ6): последний день торгов — последняя пятница месяца,
расчётная цена — среднее индекса 17:00–18:00 МСК, поэтому склейка в 15:00 UTC
(BTZ2026 → 25.12.2026). Заводится не больше трёх месяцев вперёд. Очищенный спред равен
сырому (fair = 0), правило знака для лонга выключено, как у пар с fair = 0. Стратегия
учитывает фандинг вечного: SWAPRATE с ISS в долларах за монету, ряды `swaprate_btc`
и `swaprate_eth` (`sync_funding --only BTC,ETH`). Спот — сам вечный, уровни — доли его цены.

## Запуск

Развёртывание на сервере (nginx, gunicorn, systemd, перенос базы) — `deploy/README.md`.

`.env` в корне: `DJANGO_SECRET_KEY`, `POSTGRES_PASSWORD`, `FINAM_API_SECRET`
(и при необходимости `POSTGRES_DB/USER/HOST/PORT`).

```
python manage.py migrate
python manage.py add_usd | add_eur | add_gold | add_silver | add_tri | add_btc   # нужные пары
python manage.py add_seconds        # календари и треугольники на секондах, после базовых пар
python manage.py add_brent          # BR − BZ NYMEX и месячные контракты
python manage.py add_extra_spreads  # CRCNH, SI6E, NGCAL, NGNYMEX, TRIGDS, CRSISPOT, SIEUSPOT
python manage.py add_seconds        # ещё раз после add_extra_spreads: NGNYMEX2 нужна NGNYMEX
python manage.py sync_rates
python manage.py sync_funding
python manage.py sync_bars          # 5-минутки за 30 дней (--days, максимум 120), часы — из них
python manage.py build_spread
python manage.py runserver
```

Поиск инструментов Finam: `python manage.py finam_search NG --mic EDT` — по части
тикера, символа или названия и по части MIC (`--mics` — все биржи, `--bars` —
сколько часовых баров у найденных). Список всех активных инструментов
скачивается постранично из `/v1/assets/all` раз в сутки в `var/finam_assets.json`.

Постоянно работают `run_live` (Finam), для крипты `run_bybit` и, для радара, `run_radar`.
`run_live` подписывается на котировки Finam — по одному символу на подписку (списком Finam
отвечает «Maximum number of symbols exceeded» и не шлёт ничего), часовых баров сокета не берёт:
час и 5 минут собираются из котировок, раз в 5 минут их заменяют 5-минутки биржи (REST),
а часы пересобираются из них. При переподключении разрыв догружается теми же 5-минутками
(не глубже 3 дней, глубже — `sync_bars`/`sync_m5`). `run_live` копит котировки в памяти
и раз в 5 с пишет их пачкой,
затем пересчитывает хвост spread_rate у пар, где что-то поменялось
(календари и треугольники — вслед за своими ногами). Раз в сутки обновляет
ставки и фандинг. Символы фронта и секонда пересчитываются при каждом
переоткрытии сокета (раз в 11 минут), недостающий квартал или месяц заводится сам.
Пару USD заводит `add_usd` (`fix_usd` правит спот и масштаб у заведённой раньше вручную).

## 5-минутные свечи (этап 1 таймфреймов)

Отдельная таблица `MinuteCandle` (`market/minutes.py`): часовая цепочка её не видит.
- `sync_m5` — из Finam по актуальным ногам: фронт и секонд каждой пары, вечный и спот
  (`--dry-run` — список, `--pair USD`, `--full` — заново всю глубину). Finam хранит M5
  на всю жизнь контракта, но отдаёт не больше ~30 дней за запрос: грузим окнами по 28.
  Вечный и спот — с первой 5-минутки кварталов пары.
- `import_tv` для файлов TradingView с шагом 5 минут («, 5_…») пишет и часы, и 5-минутки.
- `run_live` собирает 5-минутки из котировок (видно сразу) и раз в 5 минут заменяет их
  барами биржи по REST; после простоя добирает до 3 дней, глубже — `sync_m5`.

Спред 5 мин — таблица `SpreadBarM5`, тот же пересчёт на 5-минутках:
`build_spread --frame M5` (все пары, кроме Bybit), онлайн — хвост раз в 30 с с запасом 2 дня.
Нога без свечи в 5-минутке — нет бара, кроме спотов металлов у TRIGDS/TRISVS и CNH/6E
у кросс-пар: им подставляется последняя цена не старше часа и только в их сессию.
15 минут собираются из 5 при запросе.

Таймфреймы графика (`charts/frames.py`, выбор в шапке, параметр `tf`): 5м — `SpreadBarM5`,
15м — собранные из 5м, 1ч — `SpreadBar`, 4ч — собранные из часов (UTC 00/04/08/…). Свеча
старшего — open первого бара, крайние high/low, close последнего; склейка внутри интервала —
только новый контракт. На 5м и 15м окно — не больше 3 контрактов (сервер обрезает с начала),
стратегия считается на том же таймфрейме и окне; «тихая зона» у склейки — те же 26 часов
в барах таймфрейма. Окно контрактов — своё у 5м/15м. Рисунки — одни на все таймфреймы
(точки во времени и цене); опубликованные каналы тоже видны везде. Точка встаёт на бар текущего
таймфрейма (12:35 на часе → 12:00), в хранилище остаётся исходная. Шкала даёт место каждому
торговому слоту внутри сессии, даже без сделок (пропуски короче 6 ч), поэтому номер бара
пропорционален торговому времени и канал одинаков на 5м и 1ч; оповещения считают так же. Канал хранит таймфрейм,
на котором нарисован; оповещения считают границы
по барам этого таймфрейма (5м/15м — после пересчёта 5 мин, 1ч/4ч — после часового).

Свечи графика: тело — открытие и закрытие бара спреда. Тени 1ч (а из них 4ч) — настоящий
ход спреда по его 5-минутным барам внутри часа; без 5-минуток — из свечей ног, считая, что
ноги движутся вместе (максимум − максимум, минимум − минимум; каждый бар — по своему кварталу).
У треугольников синтетическая нога — произведение независимых цен (золото в $ × курс), её
тень так не оценить: без 5-минуток спреда свеча треугольника — одно тело. 15м — из 5м. Онлайн часы ног собираются из 5-минуток бирж
(раз в 5 мин): 1ч и 5м согласованы; неполный первый час после простоя не перезаписывается.

Сессии (`market/sessions.py`): ФОРТС будни 04:00–20:50 и сессии выходного дня 07:00–16:00
UTC, споты металлов будни 06:00–16:00, CME/NYMEX вс 22:00 — пт 21:00. Выходные часы ФОРТС
теперь пишутся онлайн и входят в треугольники, шкалу графика и оповещения.

## График

`/` — спред, индикатор кэрри и PnL стратегии. Уровни, режим входа, усреднение
и цена часа (закрытие, открытие, (O+C)/2) хранятся в браузере у каждого пользователя
и уходят параметрами в `/api/spread/`. Стратегия считается на лету и в базу не пишет.
Без своих уровней берутся сохранённые у пары.
Ответ сжимается gzip, а без новых баров отдаётся как 304 по ETag;
скрытая вкладка сервер не опрашивает.
Порядок пар в списке спредов меняется перетаскиванием внутри групп Front и Second
и тоже хранится в браузере.
Рисунки: Ctrl+Z отменяет, Ctrl+Y или Ctrl+Shift+Z повторяют (в любой раскладке), то же —
кнопки на панели рисования. Перетаскивание или подбор цвета — один шаг, история
своя у каждой пары и сбрасывается при её смене или перезагрузке страницы.
Переключатель «график стратегии» в панели «Стратегия» включает стратегию: панель PnL
и сделки на спреде. По умолчанию выключен, и тогда стратегия не считается вовсе —
ни уровни на сервере (`strategy=off`), ни канал в браузере. Выбор хранится в браузере.
Кнопка с фотоаппаратом (Alt+S) копирует изображение графика со всеми панелями и
легендами в буфер обмена; по http без https буфер браузеру недоступен, тогда
снимок скачивается PNG-файлом. Легенда индикатора «фандинг − контанго»
показывает итог и отдельно фандинг и контанго в тех же единицах.

Уровни стратегии — доли спота каждого часа: линии на графике идут за спотом, ровно
там, где их проверяет движок (а не по последней цене). Тейк закрывает 1 ед., остаток —
последний тейк; «весь объём по первому тейку» (`tp=all`) закрывает всё сразу. Легенда
PnL делит итог на контанго (движение спреда), фандинг и комиссии с начала контракта.
Если очищенный спред совпадает с сырым, рисуется одна линия; цвета линий — в шапке.

Стратегия «Канал» (вкладка «Стратегия» → «Канал») считается в браузере по уже
загруженным барам, сервер в этом режиме стратегию не гоняет (`strategy=off`).
Канал — рисунок «Параллельный канал»; границы — по номеру бара на шкале, как
канал виден на экране. Лонг от нижней границы, шорт от верхней; варианты: стороны,
вход касанием или возвратом в канал, выход на середине, у противоположной границы
или на доле ширины, стоп за границей в долях ширины, переворот, продление вправо,
фандинг (те же ряды, что у движка), издержки за круг. На склейке позиция закрывается.

`run_strategy --pair CNY` — то же в консоли с уровнями пары: закрытые сделки
пишет в `PaperTrade`, открытую позицию держит в `PositionState`.

## Радар

Страница `/radar/`: следы крупных участников по ногам спредов и инструментам
из админки (Радар → Инструменты радара: корень квартала `RI`, `MX` — фронт и
склейка выбираются сами, или символ Finam `IMOEXF@RTSX`; там же пороги).
Строка без галочки «следить» убирает инструмент из радара, даже если это нога
спреда: символ (`SiH7@RTSX`) или корень квартала (`Si` — все контракты Si).

Страница — терминал из виджетов (GridStack): список инструментов, график
(минуты, дельта, ОИ, маркеры), стакан, лента, аномалии. Двигать, растягивать и
убирать виджеты можно после кнопки «Редактировать» (выход — «Готово»), иначе
сетка неподвижна и не мешает графикам. Клик в списке или в ленте аномалий
меняет инструмент во всех виджетах; выбор в заголовке виджета — только в нём
(📌 возвращает к общему). Раскладка хранится в браузере (`radar-layout-v2`,
старая раскладка переносится сама), «Вернуть раскладку по умолчанию» — в меню «+ Виджет».
Данные всех виджетов приходят одним запросом `/api/radar/state/?books=…&tapes=…&feeds=…`.
Запускается отдельно, в своём терминале:

```
python manage.py run_radar            # --dump 20 — напечатать первые сообщения сокета как есть
```

Процесс подписывается на стакан (`ORDER_BOOK`) и ленту (`INSTRUMENT_TRADES`)
Finam, при подключении и раз в минуту сверяет стакан REST-ом. Раз в секунду
пишет: сделки (хранятся 3 дня), минуты со стороной агрессора и открытым
интересом (год), аномалии (90 дней), верх стакана — одна строка на символ.

Детекторы считают пороги по истории самого инструмента. Числа ниже — значения
по умолчанию, все они правятся в админке (см. «Правила сигналов»):

| Тип | Что значит |
|---|---|
| крупная сделка | заявка одной стороны (серия сделок подряд) больше 99,5-го процентиля размеров |
| проход по стакану | такая заявка прошла 3 и больше уровня, объём больше 99-го процентиля |
| стена | уровень выше 99,5-го процентиля уровней инструмента и в 5 раз больше медианного, простоял 30 с |
| стена снята / съедена | стена ушла: исполнено больше половины — съедена; меньше и в 3 уровнях от лучшей цены — снята (похоже на спуфинг) |
| всплеск объёма | минута против той же минуты прошлых дней (или последних часов), робастный z ≥ 5 |
| скачок ОИ | изменение открытого интереса за минуту, робастный z ≥ 6, с толкованием по цене |

Первые часы после запуска радар набирает статистику, аномалий почти нет: стены ищутся
после ~3 минут истории стакана. Одно событие по стенам на символ и сторону в минуту.

**Правила сигналов** (админка → Радар → Правила сигналов, `radar/rules.py`).
У каждого сигнала своя строка: включён ли он, порог, кратность, число уровней,
промежуток между сделками одной заявки, время подтверждения стены, окно в
минутах (объём и ОИ) и пауза между повторами. Поле «для кого»: пусто — для
всех, корень квартала (`Si`) — для всех его контрактов, символ (`SiZ6@RTSX`) —
для одного; пустые поля такой строки берутся из общего правила. Правила
создаёт миграция с прежними значениями; `run_radar` перечитывает их раз в
30 секунд, перезапуск не нужен. Окно больше минуты сравнивает сумму объёма
(изменение ОИ) за окно с такими же окнами за последние сутки.
Нет `FINAM_API_SECRET`, `ALGOPACK_TOKEN` или самого `run_radar` — страница
рисуется и в шапке пишет, что не подключено. AlgoPack пока только проверяет
токен; FUTOI, Super Candles и HI2 подключатся следующим этапом.

## Доступ: «Отдел трейдинга» и «Просмотр»

Без личных аккаунтов: при первом заходе — страница `/enter/` с выбором группы.
«Отдел трейдинга» входит по паролю `ANALYST_PASSWORD` из `.env`, «Просмотр» — без пароля.
Группа хранится в сессии на год: при повторном заходе сразу график. Кнопка
«… · выйти» в правом нижнем углу (с подтверждением) возвращает к выбору.
Сменили пароль аналитиков — все аналитики входят заново. Админка — свой вход.

Зритель (проверка на сервере, `access/middleware.py`): только график, его данные,
список пар и опубликованные каналы. Аналитика, радар, Excel, публикация — закрыты,
даже если набрать адрес. Пары — только с галочкой «для зрителей» в админке
(Пары → «для просмотра»; по умолчанию TRIGDS, TRISVS, USD, CNY, EUR). Стратегий, уровней,
индикаторов и рисования у зрителя нет; цвета спреда, каналов и тема — свои.

Публикация: аналитик выделяет параллельный канал → «опубликовать» (с подтверждением).
На сервер уходит точная копия рисунка и линия, на которой он нарисован (сырой или
очищенный), таблица `charts.PublishedChannel`. Повторная публикация того же
канала обновляет его, «снять» — убирает у зрителей. Удалили у себя опубликованный
канал — страница спросит, снять ли его и у зрителей (иначе у зрителей он останется;
снять можно и в админке). Зрители видят каналы закреплёнными: версия публикаций
приходит в каждом ответе `/api/spread/`.

Оповещения (`charts/alerts.py`): после пересчёта пар `run_live` проверяет
опубликованные каналы и пишет в Телеграм-чат `TELEGRAM_CHAT_ID` ботом
`TELEGRAM_BOT_TOKEN`: касание верхней или нижней границы и переход середины,
по последнему бару, одно и то же событие не чаще раза в час. Проверка связи —
`python manage.py telegram_test` (`--check` — сразу проверить каналы).

Личные алерты (`charts/user_alerts.py`, таблица `charts.Alert`) — только у отдела
трейдинга, в «Просмотр» не попадают. Вкладка с колокольчиком на правой панели:
пока она открыта, на графике кроме обычных рисунков видны рисунки-алерты (пунктир,
сработавшие — серые); в других вкладках — только обычные. Алертом становится
нарисованный в этой вкладке канал, трендовая или горизонтальная линия, луч или
прямоугольник; обычный рисунок — «сделать алертом» в его панели. Срабатывание одно:
пересечение линии в любую сторону, у канала — касание границы и (или) достижение середины
(выбор в шестерёнке), вход в прямоугольник. В списке у алерта номер на паре (#2), ряд
(«по сырому» / «по очищенному» цветом линии) и числа рисунка; клик по строке выделяет
рисунок на графике; ⏸ / ▶ — выключить, не удаляя, и включить снова. Канал, трендовая линия и луч могут повторяться
(шестерёнка → «после срабатывания»: пауза 5 мин, 15 мин или 1 ч между сообщениями). Уровень
можно задать с клавиатуры во вкладке: в единицах спреда — горизонтальная линия, в % спота —
линия по споту каждого бара, как уровни стратегии (меняется в шестерёнке).
За 4 часа до склейки контракта пары ждущие алерты снимаются сами (`ROLL_OFF` в
`charts/user_alerts.py`), в чат приходит сообщение с причиной; включённый снова руками перед той же
склейкой второй раз не снимается. В списке спредов у пары с ждущими алертами — оранжевая точка.
Вкладка «Лоты» на правой панели — соотношение лотов для сделки (`charts/lots.py`, `/api/lots/`): стоимость лота каждой ноги
ФОРТС в рублях = цена × STEPPRICE / MINSTEP из ISS Мосбиржи, самая дорогая нога — 1 лот, при ошибке
округления больше 3 % ещё «точнее» (до 10 лотов дорогой ноги). У CRCNH, SI6E, CRSISPOT, SIEUSPOT —
только CR, Si, Eu; у NG/BR с NYMEX — константа 100 : 1; у календарей строки нет.
Вкладка «Фандинг» (`rates/expected.py`, `/api/funding/`) — для пар с вечным: ожидаемый фандинг
на сегодня (SWAPRATE из текущих данных торгов ISS), F_lastday и средние за 3/5/10 дней из
`FundingDay`, % годовых = фандинг / цена вечного × 365. Сообщение алерта — коротко: заголовок
жирным, событие, время (`message()` в `charts/user_alerts.py`). Текст сообщений —
`message()` в `charts/user_alerts.py` (опубликованные каналы — `message()` в `charts/alerts.py`).
`run_live` проверяет алерты сразу после пересчёта спреда (раз в 3 с, `LIVE_FLUSH_SECONDS` в `.env`;
длительность пересчёта — в минутной сводке лога) по последнему
значению; алерт ждёт, пока по всем ногам в этот день (по Москве) были сделки, последняя
сделка каждой ноги не старше 2 минут (6E, CNH, USDCNY, EURUSD — 4 минут; `FRESH`, `FRESH_SLOW`)
и в стакане каждой ноги есть покупатели и продавцы. Стакан ног пар с ждущими алертами
`run_live` берёт сам (подписка ORDER_BOOK, список обновляется при переподключении сокета,
раз в 11 минут); без неё — стакан радара `run_radar`, если он запущен; нет ни того, ни
другого — стакан не проверяется, в сообщении так и сказано. Время сделок — лента радара
или котировки сокета `run_live`. Шестерёнка в строке
списка — по какому спреду алерт: сырому или очищенному.
Сообщение — с возрастом последней сделки каждой ноги, в чат `TELEGRAM_ALERT_CHAT_ID`
(тот же бот) и всплывающим окном на открытой странице. Сработавший включается снова
кнопкой ↻ в списке.

## Аналитика

Страница `/analytics/` — статистика контрактов пары по дням до экспирации
(по мотивам `gas_spreads.py`): выбор пары, ряда (сырой или очищенный), месяца
контракта или всех, исключение отдельных контрактов, параметры сделки.
Четыре графика: спред каждого контракта по дням до склейки (линии — годы),
сетка «вход × выход» с доходом сделки (% за период, годовых или доход/разброс),
движение к нулю и куда шёл спред (лонг/шорт) — обе в масштабе каждого контракта;
ниже — лучшие диапазоны. Идущий контракт в статистику не входит. Расчёт —
`analytics/core.py` на numpy, кэшируется до новых баров пары.

Шаг сетки — 4, 8 или 16 часов (по умолчанию 8): часовой ряд контракта делится
на шаги «часов до склейки / шаг», пустые шаги (ночь, выходные) берут ближайшее
значение не дальше 3 дней. Клеток по оси не больше 300: для длинного окна шаг
сам становится крупнее (квартал — 8 ч, два квартала — 16 ч), подпись карты это
пишет. Удержание, сглаживание и зоны — в днях, в API `step=24` даёт прежнюю
дневную сетку. Ответ отдаёт строки сеток только до последнего выхода (нижний
треугольник), так он не больше прежнего.

Вейвлет (`wavelet=1`, `analytics/denoise.py`): Добеши 4, мягкий универсальный
порог по шуму самого мелкого уровня. Сглаживается часовой ряд каждого контракта
до деления на шаги и дневной ряд фандинга. Сглаживание видит весь ряд, включая
будущее: доход на картах выглядит лучше реально достижимого — сверяйте без него.

Карта фандинга — у пар с вечным (как у стратегии, `strategy.runner.funding_of`),
по дням: фандинг на единицу актива от входа до выхода, знак — для лонга спреда
(шорт вечного), медиана по годам. Три вида: % капитала за удержание, % годовых,
средняя ставка к цене. Дни до запуска вечного в расчёт не идут.

Зависимости `numpy` и `PyWavelets` — в `requirements.txt`; на ВМ после
обновления: `pip install -r requirements.txt` и перезапуск `web`. Если nginx
не сжимает ответы, добавьте `gzip on; gzip_types application/json;` — карта
до ~5 МБ JSON сжимается в несколько раз.

История контракта на странице длиннее его окна торговли: спред считается из
свечей за два месяца до склейки у месячных (BRNYMEX, NGNYMEX, NGCAL) и за два
квартала у квартальных (`HISTORY_MONTHLY`, `HISTORY_QUARTERLY` в
`strategy/rebuild.py`). Окна соседних контрактов при этом перекрываются, поэтому
история лежит в своей таблице `analytics_historybar` (ключ — пара, контракт, час);
в `strategy_spreadbar` (график, стратегия) по-прежнему только окно. Таблицу
заполняют `build_spread` и `build_analytics [--pair X]`, страница сама
дорисовывает пару раз в день. Нужны свечи за этот срок: `import_tv` грузит
файл целиком, `sync_bars` тоже берёт следующие контракты с запасом истории.

Кварталы Si и Eu — в рублях за 1000 долларов или евро, пары USD и EUR делят их
на `future_scale` 1000. `fix_quarters --dry-run` показывает по каждому кварталу
чужой пары и неверные окна, а также свечи вечного, спота и кварталов в другом
масштабе. Эталон масштаба — последние 7 дней свечей пары (Finam, живой поток),
кварталы делятся на scale; свеча, отличающаяся от него в ~1000 раз, делится
или умножается на 1000 (`market/units.py`). Без `--dry-run` всё это
исправляется, затем пересчитываются спред и аналитика. `import_tv` делает ту же
проверку при загрузке: файл TradingView `RUS_USDRUBF_1000` (вечный ×1000)
записывается уже делённым на 1000.
Другой корень: `fix_quarters --root CR --pair CNY`.

История — та, что накопилась в `strategy_spreadbar`. Старые контракты можно
загрузить выгрузками TradingView («Экспорт данных графика», CSV):
`python manage.py import_tv папка/` (сначала с `--dry-run`) — инструмент по
имени файла (`CRZ2023`, `CNYRUBF`); недостающий контракт заводится сам: квартал
Мосбиржи — у пары с этим корнем, NG — по бирже в имени файла (`NYMEX_…NGG2021`
— окно NGNYMEX, иначе нога Мосбиржи), BR/BZ — у BRNYMEX, CNH/6E — у кросс-пар;
затем `build_spread`.
Автоматически качать из TradingView нельзя: официального API нет.
